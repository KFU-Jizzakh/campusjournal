# SPEC-24: Публичная видимость выпусков

Публичный сайт показывает только опубликованные выпуски: запланированные выпуски и выпуски в работе недоступны читателям (404), на главной нет блока «Запланированные выпуски», а инвариант «опубликованная статья ⇒ опубликованный выпуск» гарантирует, что ни одна публичная страница не может сослаться на скрытый выпуск.

Depends on: SPEC-04, SPEC-09, SPEC-11 | —

Status: DRAFT

## Acceptance Criteria

- AC-1: Страница `/issues` показывает только выпуски со статусом `published`.
- AC-2: Страница `/issues/{issue}` для выпуска со статусом `planned` или `in_progress` возвращает 404; для `published` — 200 с содержанием.
- AC-3: На главной странице нет секции с запланированными выпусками.
- AC-4: `Article::publish()` в выпуск, не имеющий статуса `published`, бросает `DomainException`; статья не публикуется.
- AC-5: Смена статуса опубликованного выпуска на `planned`/`in_progress` заблокирована, пока в выпуске есть опубликованные (`published`/`retracted`) статьи (в Filament — уведомление об ошибке, запись не сохраняется).
- AC-6: Сохранение статьи со статусом `published`/`retracted`, привязанной к выпуску без статуса `published` (например, из Filament), бросает `DomainException`.
- AC-7: OAI-PMH `ListSets` содержит только опубликованные выпуски.
- AC-8: Форма публикации в дашборде редактора предлагает только опубликованные выпуски.

## UI/UX Notes

- Страница выпуска не содержит ветки «Выпуск ещё не опубликован» — она недостижима, так как неопубликованные выпуски возвращают 404.
- В Filament редактирование выпуска при попытке понизить статус показывает уведомление об ошибке без сохранения.

## Business Rules

- BR-1: Инвариант: опубликованная (`published`/`retracted`) статья может находиться только в опубликованном выпуске.
- BR-2: Неопубликованные выпуски (`planned`, `in_progress`) недоступны ни по какому публичному маршруту (списки, страницы, sitemap, OAI-PMH).
- BR-3: Sitemap включает только опубликованные выпуски (SPEC-11/BR-1).
- BR-4: Статус `published` — единственный источник публичной видимости выпуска; `published_at` не влияет на видимость.

## Behavior

### Background

Given администратор создал выпуски со статусами `published`, `planned` и `in_progress`

### Rule: Публичная видимость (BR-2)

#### Scenario: Страница неопубликованного выпуска

Given выпуск со статусом `planned`
When  посетитель открывает `/issues/{issue}`
Then  ответ 404
And   страница выпуска не рендерится

#### Scenario: Главная без запланированных выпусков

Given выпуск со статусом `planned`
When  посетитель открывает главную страницу
Then  название запланированного выпуска не отображается

#### Scenario: OAI-PMH sets

Given выпуск со статусом `planned`
When  агрегатор запрашивает `ListSets`
Then  выпуск отсутствует в ответе

### Rule: Инвариант статья↔выпуск (BR-1)

#### Scenario: Публикация в неопубликованный выпуск

Given статья в статусе `approved` и выпуск со статусом `planned`
When  редактор публикует статью в этот выпуск
Then  бросается `DomainException`
And   статья остаётся в статусе `approved` без `issue_id` и `published_at`

#### Scenario: Понижение статуса выпуска с опубликованными статьями

Given выпуск со статусом `published`, содержащий опубликованную статью
When  администратор меняет статус выпуска на `planned`
Then  бросается `DomainException`
And   статус выпуска остаётся `published`

#### Scenario: Понижение статуса выпуска только с ретрагированными статьями

Given выпуск со статусом `published`, содержащий только ретрагированную статью
When  администратор меняет статус выпуска на `planned`
Then  бросается `DomainException`
And   статус выпуска остаётся `published`

#### Scenario: Понижение статуса пустого выпуска

Given выпуск со статусом `published` без опубликованных статей
When  администратор меняет статус выпуска на `planned`
Then  статус сохраняется

#### Scenario: Привязка опубликованной статьи к неопубликованному выпуску в Filament

Given статья со статусом `published` и выпуск со статусом `in_progress`
When  администратор сохраняет статью с `issue_id` этого выпуска
Then  бросается `DomainException`
And   изменения не сохраняются
