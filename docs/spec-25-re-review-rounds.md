# SPEC-25: Повторные раунды рецензирования и письмо с ответом рецензентам

Редакция может направить рукопись на повторный раунд рецензирования: после решения «доработка» автор повторно подаёт рукопись вместе с обязательным письмом с ответом рецензентам, раунд статьи увеличивается, и редактор может повторно пригласить рецензентов завершивших прошлый раунд. Решение принимается только по рецензиям текущего раунда.

Depends on: SPEC-01, SPEC-02, SPEC-03, SPEC-04 | —

Status: DRAFT

## Data Model

| Поле | Тип | Описание |
|------|-----|----------|
| `reviews.round` | smallint, default 1 | Раунд, в котором создано назначение рецензии |
| `articles.current_round` | smallint, default 1 | Текущий раунд статьи |
| `response_letters.article_id` | FK → articles | Статья |
| `response_letters.round` | smallint | Раунд, которому отвечает письмо |
| `response_letters.body` | text | Текст письма |
| `response_letters.file_path` | string, nullable | Приложение (PDF/DOCX), disk `local` |
| `response_letters.uploaded_by` | FK → users, nullable | Автор письма |

Частичный уникальный индекс `reviews_article_reviewer_active_unique` пересоздан как `(article_id, reviewer_id, round) WHERE status != 'declined'`.

## Acceptance Criteria

- AC-1: Повторная подача после решения «доработка» увеличивает `current_round` статьи на 1 и переводит её в `submitted`.
- AC-2: Повторная подача требует непустого письма с ответом рецензентам (`response_letter`); письмо сохраняется с раундом нового раунда, опционально с файлом приложения.
- AC-3: Редактор может повторно назначить рецензента, завершившего рецензию в прошлом раунде; рецензент получает уведомление `ReviewReRequested`, а письмо о назначении указывает раунд.
- AC-4: Повторное назначение запрещено, если у рецензента есть неотклонённая рецензия в текущем раунде (ошибка дубликата).
- AC-5: Решение (`decide`) возможно только при наличии завершённой рецензии текущего раунда; рецензии прошлых раундов для решения не засчитываются.
- AC-6: Повторная подача очищает слепой PDF предыдущего раунда (`blinded_pdf_path/at/by`), чтобы double-blind раунд 2 не получил устаревший анонимизированный файл.
- AC-7: Письмо с ответом видно: редакции (все раунды), автору (свои письма), рецензенту раунда — письмо своего раунда; скачивание файла приложения закрыто `ResponseLetterPolicy`.

## UI/UX Notes

- Карточки рецензий на страницах редакции и автора показывают бейдж «Раунд N» (для раундов > 1).
- Форма повторной подачи показывает комментарий редакции и отзывы рецензентов текущего раунда над полем письма.
- Страница рецензента показывает письмо автора своего раунда и собственную завершённую рецензию прошлого раунда.
- Секция «Письма авторов» на странице редакции сгруппирована по раундам.

## Business Rules

- BR-1: Решение принимается только по завершённым рецензиям текущего раунда (`reviews.round = articles.current_round`).
- BR-2: Письмо с ответом обязательно при повторной подаче и создаётся в той же транзакции, что и `revise()`; его раунд — новый раунд статьи.
- BR-3: Проверка дубликата назначения скоупирована текущим раундом (как в OJS): незавершённое назначение прошлого раунда повторное приглашение не блокирует.
- BR-4: Видимость письма: редакция — все письма статьи; автор и соавторы — все свои письма; рецензент — письмо раунда, в котором он назначен.
- BR-5: `Completed`/`Declined` остаются терминальными статусами рецензии; повторный раунд — всегда новая строка `reviews`.

## Behavior

### Background

Given статья в статусе `in_review` с завершённой рецензией рецензента Р раунда 1
And редактор вынес решение «доработка»

### Rule: Новый раунд (AC-1, AC-6)

#### Scenario: Повторная подача
When автор повторно подаёт рукопись с письмом с ответом
Then `current_round` статьи равен 2 и статус `submitted`
And слепой PDF прошлого раунда удалён

### Rule: Письмо с ответом (BR-2)

#### Scenario: Письмо сохранено в новом раунде
When автор подаёт письмо с ответом (с файлом или без)
Then существует `response_letters` с `round = 2`, телом письма и `uploaded_by` автора

#### Scenario: Отсутствие письма
When автор повторно подаёт рукопись без письма
Then валидация отклоняет подачу с ошибкой `response_letter`
And статья остаётся в статусе `revision`

### Rule: Повторное назначение (BR-3)

#### Scenario: Re-request завершившего раунд рецензента
When редактор назначает рецензента Р в раунд 2
Then создаётся рецензия раунда 2 и Р получает `ReviewReRequested`
And письмо о назначении содержит отметку «Раунд рецензирования: 2»

#### Scenario: Дубликат в текущем раунде
When редактор повторно назначает рецензента с незавершённой рецензией текущего раунда
Then назначение отклоняется с ошибкой дубликата

### Rule: Решение по текущему раунду (BR-1)

#### Scenario: Только рецензии прошлого раунда
When редактор пытается вынести решение без завершённой рецензии раунда 2
Then решение отклоняется: «Необходимо дождаться хотя бы одной завершённой рецензии текущего раунда»

#### Scenario: Завершена рецензия текущего раунда
When рецензия раунда 2 завершена и редактор принимает статью
Then статус статьи `accepted`

## Notes

- Статистика (`ReviewerStats`, `EditorialStats`) включает рецензии всех раундов — осознанное решение (трудозатраты рецензента считаются по всем раундам).
- Незавершённое назначение прошлого раунда (рецензент не принял/не завершил) не блокирует повторное приглашение в новом раунде; автоматической отмены нет (как в OJS, где отмена — отдельное ручное действие редактора).
